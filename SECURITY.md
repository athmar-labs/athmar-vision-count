# Security Policy

## Supported releases

Security fixes are provided for the latest production release and the active paid pilot branch only. Prototype branches and locally modified customer builds are not supported unless covered by a written support agreement.

## Reporting a vulnerability

Do not open a public issue for a suspected vulnerability, exposed credential, customer data leak, or model/data licensing concern.

Use GitHub's private vulnerability reporting or a private security advisory for this repository. Include:

- affected version or commit;
- device and Android version;
- reproduction steps;
- expected and observed behavior;
- impact assessment;
- logs or screenshots with customer data removed.

Athmar Labs will acknowledge a complete report, assess severity, and coordinate remediation and disclosure. Do not access, retain, or distribute customer data beyond what is strictly necessary to demonstrate the issue.

## Security requirements

- No API keys, passwords, signing keys, customer images, customer datasets, or production model files may be committed.
- Release builds must be generated by the protected production environment in GitHub Actions and signed with customer-approved credentials.
- Network synchronization is disabled by default and may only target an approved HTTPS endpoint.
- Count exports require human confirmation.
- Captured images are not stored by the privacy-first release.
- Dependencies and Unity editor versions are pinned and reviewed before upgrades.

## Incident response

For a confirmed incident, stop distribution of the affected build, revoke exposed credentials, preserve relevant logs without customer content, notify affected parties under the applicable agreements, and publish a patched signed release after validation.
